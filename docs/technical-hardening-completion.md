# گزارش مرحله تکمیلی سخت‌سازی پروژه

## تغییرات این مرحله

- مدل `VendorUser` برای اتصال حساب کاربری به فروشنده، با نقش و وضعیت فعال، محدودیت یکتایی و امکان مدیریت از Django Admin اضافه شد.
- مدل‌های `Document` و `DocumentVersion` از حالت خالی خارج شدند: مالکیت بر اساس مشتری/پروژه/فروشنده، بارگذار، نوع سند، محرمانگی، فایل، SHA-256 و شماره نسخه اضافه شده‌اند.
- ایجاد سند از API اعتبارسنجی tenant و اندازه فایل (حداکثر ۲۵ MiB) دارد؛ دانلود فایل از endpoint احراز هویت‌شده و دارای scope انجام می‌شود.
- محدودسازی API فروشنده به Vendorهای متصل و پروژه‌ها/سفارش‌های خرید وابسته به آن‌ها اضافه شد.
- تست‌های واحد scope برای فروشنده/سند و تست API برای جلوگیری از مشاهده یا تغییر پروژه مشتری دیگر اضافه شدند.
- Workflow CI برای اجرای migration check، اعمال migration روی PostgreSQL، تست‌های Django/pytest و build/test فرانت‌اند اضافه شد.
- دسترسی API سند فقط پس از اعمال migrationهای جدید معتبر است؛ migrationها هنوز در این محیط قابل تولید نبودند.

## وضعیت اعتبارسنجی

- بررسی نحوی پایتون (`compileall`) و اسکریپت shell موفق است.
- فایل‌های Compose و lockfile از مرحله قبلی بررسی شده‌اند.
- تست‌های Django/API، ارتقای دیتابیس واقعی، build فرانت‌اند و آزمون یکپارچه در این محیط اجرا نشدند؛ Django در محیط نصب نیست و نصب وابستگی‌ها به علت نبود دسترسی شبکه ممکن نشد.
- **مانع انتشار:** برای ۸ اپلیکیشن `accounts`, `clients`, `projects`, `inspections`, `notifications`, `reports`, `mts`, `documents` هنوز migrationهای versioned وجود ندارد. اجرای `scripts/generate_migrations.sh` در محیط دارای وابستگی‌ها، بازبینی فایل‌ها، commit و سپس اجرای کامل CI الزامی است.

## پیش از انتشار

1. در محیط توسعه با `backend/requirements/development.txt` نصب‌شده، `scripts/generate_migrations.sh` را اجرا و migrationهای تولیدشده را بازبینی کنید.
2. روی دیتابیس PostgreSQL خالی و یک کپی از دیتابیس نسخه قبلی، `migrate --plan` و `migrate` را اجرا کنید؛ مسیر ارتقا و بازیابی را ثبت کنید.
3. کل workflow CI را اجرا کنید و هر تست شکست‌خورده را رفع کنید. پوشش تست دسترسی بین مشتریان را برای هر endpoint و action سفارشی گسترش دهید.
4. برای آپلودها storage خصوصی، اسکن بدافزار، محدودیت نوع واقعی فایل و سیاست retention اضافه کنید؛ پسوند فایل به تنهایی اعتبارسنجی امنیتی کافی نیست.
5. TLS، secret rotation، پشتیبان‌گیری رمزگذاری‌شده خارج از سرور، بازیابی رسانه‌ها، هشدار شکست backup و پایش متمرکز را در محیط واقعی اثبات کنید.
